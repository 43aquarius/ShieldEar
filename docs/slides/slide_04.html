总体架构
ARCHITECTURE
一份引擎，跑在两端——谁也糊弄不了谁

浏览器先判一遍、服务端再核一遍，跑的是同一份 TypeScript 引擎：录音文件与实时通话的结论完全一致，客户端结果可被独立复核。检测不快不行、存证不严不行——这两个要求决定了下面五层。

L1 采集 —— 麦克风实时流（AudioWorklet 16kHz）· 文件导入 · TTS现场合成，统一为单声道标准输入

L2 检测引擎

纯 TypeScript 零依赖，八维特征 + 2s 窗 / 1s 步进 / 50% 重叠滑窗

「全片最厚的一层——左右两端跑同一份代码」

L3 判决融合 —— 中值滤波 + 指数平滑 + 能量加权整段判决，静音窗显式排除、不参与统计

L4 业务 —— SHA-256 证据固定 · 案件入库 · 可导出核验报告

L5 展示 —— 单页应用零跳转，答辩演示全程不切屏

为什么敢说能落地
普通 CPU

无需 GPU，浏览器与服务端皆可跑

Next.js + TS

一套语言栈贯穿前后端与引擎

SQLite

案件与证据链本地落盘，可审计

Next.js 16 · TypeScript · Prisma/SQLite · Web Audio API

同构引擎的价值：检测结论不因端而异——这是证据链成立的技术前提。
架构五层，从下往上过一遍：L1采集，把麦克风实时流、文件导入和现场合成统一成单声道标准输入；L2是全片最厚的检测引擎，纯TypeScript零依赖，八维特征加2秒窗、1秒步进的滑窗；L3用中值滤波、指数平滑、能量加权融合出整段判决；L4做SHA-256证据固定和案件入库；L5单页展示零跳转。重点是同构引擎：浏览器和服务端跑的是同一份代码，结论完全一致、可被独立复核——这是证据链成立的前提。为什么敢说能落地？纯CPU、一套语言栈、SQLite本地落盘可审计。
